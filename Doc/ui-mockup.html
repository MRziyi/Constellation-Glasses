A constellation of senses, one mind. 「万象皆星，一念至此」
by Zack 紫意 · companion to Halo Ring · package com.constellation.glass

Constellation has two surfaces on the glasses, and that's it:

  1. The HUD — a transient overlay on the right-eye JBD4020 micro-LED panel. 99 % of interaction lives here. Phase-3b model: six states, single content area, new content always replaces the old (no stacks). (§1)
  2. The app settings — a minimal, rarely-entered configuration screen for shortcut presets and the Cortex connection. (§2)

Ring + temple gestures are Halo Ring's domain when paired; without Halo Ring, voice commands via Rokid InstructSdk replace them (§1.9). Either way, Constellation declares its actions through the same Halo Ring plugin protocol (§3).

Visual language verbatim from R08-dev/Doc/ui-mockup.html (Halo Ring) — same eight tokens, same focus indicator, same HUD card shape. Phase-3b adds a monochrome-green .frame.glass variant (JBD4020-specific — colours auto-downsample to the green channel). Spec references: GLASS-CLIENT-DESIGN.md · DESIGN.md · INTERFACE-CONTRACTS.md · UI-UX.md · halo-ring-plugin-protocol.md.

§1 The HUD — six states · single content area · replace in place

The HUD is the right-eye 4:3 monochrome-green canvas. At any moment it is in one of five active states (IDLE / LISTENING / THINKING / CARD / INSIGHT) plus the OFFLINE error overlay. New content always replaces the current content — there is no card stack, no history scroll. The Halo Ring's own glanceable pip lives bottom-right; we leave that zone untouched.

v2 model — what changed from the original sketch. The HUD used to be "two atoms" (status pill + card). It's now a state machine: the wearer's journey through one turn is IDLE → LISTENING → THINKING → CARD → decision → IDLE. State transitions own the HUD lifecycle (open / update / close); content differences within a state are template variants. Card bodies arrive pre-parsed as styled runs from Cortex (§1.10) — no raw ** markdown ever touches the panel.

1.0 Canvas zones — where things live

Constellation HUD
~56 % height · single content area
unlit pixels = AR-transparent · world shows through
Halo Ring pip (their own overlay)
Right-eye canvas zoning — what's drawn vs what's transparent
The JBD4020 is a transparent AR micro-LED panel. Whatever pixels we don't light up are transparent — the wearer sees the world through them. So "leave the centre clear" doesn't mean a layout constraint; it means we simply don't put bright pixels there. Our JSON sets gravity=top_start, paddingBottom=200dp to keep our drawing inside the top band.
Two key facts about the panel. (1) CustomView is exclusive on the right-eye panel: when ours is open, no other app's CustomView shows. If Sprite assistant ("Hi Rokid") or another external-app CustomView opens, the system closes ours and we get ICustomViewCbk.onCustomViewClosed() — we go to IDLE; the next wake gesture reopens. (2) Halo Ring's pip is NOT a CustomView — Halo Ring renders it via WindowManager.TYPE_APPLICATION_OVERLAY, a system overlay drawn on top of our CustomView. Coexistence is automatic; we just leave the lower-right region of our layout dark so the pip has a clean backdrop. The mock above shows the pip for orientation — but it's rendered by Halo Ring, not by us.

1.5 State INSIGHT — proactive surfacing (Insight Engine)

Already shown as CASE B above. The state is technically a transient sub-mode of IDLE: HUD opens for a content TTL (default 8 s), then auto-closes. A voice "看一下 / engage / 听听" within the window transitions to LISTENING with insight context attached.

1.6 State OFFLINE — WSS error overlay

OFFLINE · RECONNECT
● offline · reconnecting…
last seen 4 s ago · retry in 2 s

WSS down — not a button, an error state
Triggered whenever the WSS is down > 5 s. Renders over the current state's content so the wearer knows their gestures won't reach Cortex. Auto-exits to prior state on reconnect. No "disconnect" affordance exists — the server is supposed to be always-on; offline means something is wrong.

1.8 Voice command vocabulary (InstructSdk)

Offline, sub-100 ms, zero network. Registered via com.rokid.ai.glass:instructsdk:1.1.4 per the official Rokid glass-docs. Skill ID registered at developer.rokid.com; credentials live in R08-dev/refs/sdks/rokid/CXR-M SDK/.env. Vocabulary is state-scoped: registered only for the current state, so "好" in IDLE is a no-op while in CARD it's an Approve.

§2 The app — minimal configuration only

You open this app to: (1) edit a shortcut's preset prompt; (2) point at a different Cortex address; (3) sanity-check connection. Nothing else is customisable — no HUD theming, no ttl knobs, no profile editing. Defaults handle everything.

What's NOT in this app. Gesture bindings, profiles, ring config, glasses settings — all of that lives in Halo Ring. Constellation has zero gesture UI of its own.

§3 Gestures & profiles — Halo Ring (when paired)

Halo Ring is now optional (per the Phase-3b §1.8 vocabulary, voice can replace ring gestures entirely). When paired, however, the ring is the fastest input path; the integration model below applies unchanged.

If the ring isn't paired, HaloPresenceCheck at boot returns false and we skip all profile-push calls. The InstructSdk voice vocabulary (§1.8) covers all the same actions. A later install of Halo Ring is detected via PACKAGE_ADDED and bindings activate without restart.

How a gesture reaches Constellation

  1. Wearer does a gesture (e.g. LP + SWIPE_UP) the ring sends BLE event to glasses.
  2. Halo Ring recognises the gesture, looks up the binding in the active profile, and finds it's bound to com.constellation.glass / voice_invoke.
  3. Halo Ring fires an Android Intent: sendBroadcast(Intent("com.halo.ring.action.TRIGGER") .setPackage("com.constellation.glass") .putExtra("action_id", "voice_invoke")).
  4. Constellation's TriggerReceiver wakes the foreground service, which transitions to LISTENING (mic + PCM stream) and shows the listening HUD.

What Constellation declares

A standard Halo Ring plugin ContentProvider at content://com.constellation.glass.halo_actions/list. When Halo Ring's Action Picker opens, it queries every installed plugin app for its actions list and presents them under the EXTERNAL APPS group:

action_id label group
───────────────────────────────────────────────────────────────────────

shortcut_1 Quick capture person CONSTELLATION

Full protocol spec (manifest declarations, ContentProvider schema, Intent contract, permissions) lives in halo-ring-plugin-protocol.md — that's the document you'd hand to whoever maintains Halo Ring to implement this.

This means Halo Ring needs to add plugin discovery. The integration protocol is generic (any app can register actions), so the work isn't Constellation-specific. See the handoff prompt in halo-ring-plugin-protocol.md.

§5 Notes for implementation

  • Lifecycle. One ForegroundService (always running, persistent LOW-priority notification) hosting the CXRLink instance. No visible Activity — CustomView mode renders through the system service. Survives Android 12 Doze.
  • Theme tokens. Reuse Halo Ring's HaloColors / HaloType for the app-settings screens (§2). Glass HUD has its own 3-level green palette (bright / mid / dim) — the JBD4020 compositor auto-downsamples colours to the green channel.
  • HUD overlay. CXR-L openCustomView(jsonString) + updateCustomView + closeCustomView. Always assign stable ids to nodes you'll mutate — the SDK diffs by id; missing ids cause re-create + flicker.
  • Card background. rgba(5,10,6,1) — near-black with a faint green tint to simulate the JBD4020's pixel-off region under green ambient. The "softened black" rule from R-Lab inherited.
  • STT pipeline. Glass captures 16 kHz mono PCM via cxrLink.startAudioStream(1), chunks at ~250 ms, sends as audio_chunk events over WSS. Cortex runs whisper.cpp small on the Mac mini (Metal-accelerated, mean 1.2 s for short utterances). See §1.9 benchmark.
  • Feedback loop. Tapping 改 (or LONG_PRESS via ring) on a CARD transitions to LISTENING with the existing cmd_id as context; the new utterance becomes user_decision { decision: "modify", feedback_text: "…" }. Photo on the original invoke is reused (not re-captured). See INTERFACE-CONTRACTS.md §1.5.
  • Halo Ring plugin integration. Implement the protocol in halo-ring-plugin-protocol.md — ContentProvider + BroadcastReceiver + manifest meta-data. Detect ring presence at boot via PackageManager.getApplicationInfo("com.halo.ring", 0); cache for the session, refresh on PACKAGE_ADDED. If absent, the InstructSdk vocabulary (§1.8) is the sole input — no degradation in capability.
  • HUD profile auto-switch. On every state transition where Halo Ring is paired, the ForegroundService pushes the state-specific Constellation profile via the plugin protocol's PROFILE_PUSH intent. On state exit, pop. The lifecycle is mirrored in the InstructSdk activateForState(state) call — vocabulary follows state.
  • i18n. Strings via strings.xml + strings-zh.xml. Card body is markdown; Cortex sends it pre-translated for the wearer's language. The InstructSdk vocabulary (§1.8) is registered in both languages simultaneously.
  • Power. CustomView and mic are OFF in IDLE — i.e. most of the time. WSS keepalive 15 min. No polling. updateCustomView in THINKING capped at 4 Hz to stay below the thermal-fps downshift threshold.
